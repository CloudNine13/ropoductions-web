## Findings

### Aggregate Views & Architecture Delta

- **Finding 2.1: Session Creation & Cookie Issuance Duplication in Callback Route**
  - **Source:** `src/app/api/auth/callback/route.ts:201-246` and `324-368`
  - **Description:** In the OAuth callback handler, session creation logic (UUID generation, `CreateSessionInput` construction, D1 `upsertSession` call, HMAC-SHA256 cookie signing via `signValue`, cookie header serialization, and response header configuration) is duplicated almost verbatim between the override fast-path (lines 201–246) and the active patron tier verification path (lines 324–368). The route handler has expanded to 379 lines and accumulates responsibilities from token exchange, identity fetch, admin bootstrap, override check, campaign membership query, tier calculation, AES encryption, D1 persistence, cookie issuance, and error redirects.
  - **Disposition:** *Fix now (Refactor)*. Extract a unified `issueSessionResponse` helper to eliminate duplication and reduce callback handler complexity.
  - **Prevention:** Extract shared session-issuance routines before expanding role models (e.g., Epic 5 admin tools).

- **Finding 2.2: Duplicate Cookie Quote-Stripping Logic Across Module Boundaries**
  - **Source:** `src/proxy.ts:5-8`, `src/app/(portal)/layout.tsx:12`, `src/app/(game)/play/page.tsx:14-15`, `src/lib/cookies.ts:14`
  - **Description:** The regex `.replace(/^"|"$/g, "")` for stripping surrounding quotes from RFC-compliant cookie values is independently implemented across `src/proxy.ts` (as private `unquote`), `src/app/(portal)/layout.tsx`, and `src/app/(game)/play/page.tsx`. 
  - **Disposition:** *Fix now (Hygiene)*. Export a canonical `unquoteCookieValue` helper from `src/lib/cookies.ts` and use it consistently across edge proxy, server components, and route handlers.
  - **Prevention:** Mandate that all cookie parsing and normalization utilities reside exclusively in `src/lib/cookies.ts`.

- **Finding 2.3: Next.js App Router Server Component Cookie Mutation Constraint**
  - **Source:** `src/app/(game)/play/page.tsx:22,47`, `src/app/api/auth/session/route.ts:1-31`, commit `130e20e`
  - **Description:** Next.js App Router forbids cookie mutations (such as `cookies().delete()`) inside Server Components during page renders; attempting to do so under `next start` throws `Cookies can only be modified in a Server Action or Route Handler` (caught by CI E2E). Story 2.4 solved this by introducing a Route Handler bounce pattern via `GET /api/auth/session?clear=...` that clears cookies and bounces to the target paywall redirect.
  - **Disposition:** *Accept as-is (Architectural Convention)*. Formalize this pattern in AGENTS.md and ARCHITECTURE-SPINE so future stories (e.g. Story 3.2 asset streaming and logout flows) use Route Handlers for cookie invalidation.
  - **Prevention:** Document edge runtime and App Router server lifecycle constraints in agent guidelines.

### Review Lenses (Adversarial, Edge Cases, Verification Gaps)

- **Finding 2.4: Unguarded `SESSION_SECRET` in `/api/auth/patreon`**
  - **Source:** `src/app/api/auth/patreon/route.ts:14-39`
  - **Description:** `/api/auth/patreon` checks `if (!authEnv.clientId)`, but fails to verify `authEnv.sessionSecret`. When `SESSION_SECRET` is unset, `getAuthEnv` returns an empty string, causing `signValue` to sign the PKCE verifier cookie payload with `""`. The user is redirected to Patreon, authorizes, and returns to `/api/auth/callback`, where line 90 catches the missing secret and aborts with `server_configuration_error`.
  - **Disposition:** *Fix now (Remediation)*. Add an upfront guard `if (!authEnv.clientId || !authEnv.sessionSecret)` in `/api/auth/patreon/route.ts`.
  - **Prevention:** Perform fail-fast environment secret validation at the initiation point of external authentication flows.

- **Finding 2.5: Raw JSON 500 Response on Missing Config in `/api/auth/patreon`**
  - **Source:** `src/app/api/auth/patreon/route.ts:16-28`
  - **Description:** When `PATREON_CLIENT_ID` is missing, `/api/auth/patreon` returns `status: 500` with raw JSON `{ error: { code: "MISSING_CONFIG", ... } }` directly in the browser. In contrast, all callback errors redirect to `/?auth_error=...` with a user-facing layout.
  - **Disposition:** *Fix now (UX / Remediation)*. Redirect to `/?auth_error=client_configuration_error` instead of rendering raw JSON.
  - **Prevention:** Portal navigation entry points should always redirect with user-friendly error banners rather than returning raw machine envelopes to visitors.

- **Finding 2.6: Ignored `auth_error` Query Parameter Leaves Unpledged Backers Without UI Feedback**
  - **Source:** `src/app/api/auth/callback/route.ts:271,286,297,313` vs `src/lib/paywall.ts:21-35` vs `src/app/(portal)/page.tsx:9-18`
  - **Description:** When an unpledged visitor or sub-$5 backer authorizes with Patreon, the callback handler rejects them and redirects to `/?auth_error=insufficient_pledge` (or `/?auth_error=inactive_patron`). However, `resolvePaywallType` in `src/lib/paywall.ts` only inspects `params.paywall` and `params.auth_required`. It ignores `auth_error`, causing `paywallType` to resolve to `null`. The user is returned to the homepage without any modal, banner, or explanation of why their access was denied.
  - **Disposition:** *Fix now (Remediation)*. Update `PortalPageProps` and `resolvePaywallType` to recognize `auth_error=insufficient_pledge` (mapping to `"required"`) and `auth_error=inactive_patron` (mapping to `"lapsed"`).
  - **Prevention:** Define end-to-end integration tests connecting OAuth error callback parameters to landing page presentation states.

- **Finding 2.7: Thin Re-Export Shims in Test Directory**
  - **Source:** `tests/d1-schema.test.ts:1-6`, `tests/patreon-oauth.test.ts:1-1`
  - **Description:** `tests/d1-schema.test.ts` and `tests/patreon-oauth.test.ts` are 1-line files that only re-export `./verify-d1-schema` and `./verify-patreon-oauth`. `tests/suite-manifest.test.ts` explicitly hardcodes them into a `WRANGLER_DEPENDENT` exemption set to prevent `npm run test:unit` from failing.
  - **Disposition:** *Accept as-is / Defer (Hygiene)*. The shims satisfy task names from earlier story specs while keeping `test:unit` free of Wrangler CLI dependencies.

## Acceptance Verdict

- **Verdict:** `accepted-with-open-items`
- **Criteria:** Declared
  - **FR-6 (Patreon OAuth 2.0 PKCE Authorization):** MET. Web Crypto RFC 7636 PKCE S256, state validation, access/refresh tokens encrypted at rest with AES-256-GCM in D1, initial admin secret bootstrap via `INITIAL_ADMIN_PATREON_IDS` (`system_bootstrap`).
  - **FR-7 (Tier Access Verification $5+ Threshold):** MET. Verified 5 active tiers: Ork Patron ($5), Ogre Pimp ($10), Elf Sybarite ($15), Horseman Aesthete ($25), Mind Fucker Avatar ($50). Sub-threshold (<$5) and inactive/lapsed rejected. Override short-circuit bypasses Patreon API. Centralized in pure `isAccessAuthorized(session)` policy.
  - **FR-8 (Paywall Interstitial & Renewal Prompt):** MET. Elevated `PatreonPaywallCard` and `PaywallModal` featuring all 5 supporter tiers, Lucide lock badge, and direct checkout link. Dismissible banner for `revoked`, `lapsed`, and `required` states.
  - **FR-9 (Graceful Session Re-check & Lapsed Handling):** MET. No background polling severs active gameplay; verification occurs on route navigation, page reload, and asset requests. Deleted overrides transactionally marked `revoked = 1`.
  - **D1 Database & Migrations (AD-8):** MET. `0001_initial_sessions.sql` and `0002_patron_overrides.sql` created with strict SQLite CHECK constraints and indexes. All queries use parameterized prepared statements (`db.prepare().bind()`).
  - **Security & Privacy (AD-4):** MET. Zero client token exposure. Signed HTTP-only, `SameSite=Lax`, `Secure` session cookies.
  - **Unfinished Stories:** None. All 4 stories (`2-1`, `2-2`, `2-3`, `2-4`) are completed and merged.
