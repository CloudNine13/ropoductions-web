- **Finding 4.1: Administrative Status Lag on Story 4.4 in Sprint Tracking**

However, `sprint-status.yaml` was left with status `review` rather than transitioning to `done` post-merge.   - **Disposition:** *Fix now (Process / Sprint Status)*. Reconcile `sprint-status.yaml` to mark `4-4-save-import-validation-dialog-safe-storage-reset-modal` as `done`.
  - **Prevention:** Include automated sprint status update confirmation in post-PR merge checklists.

- **Finding 4.2: Architectural Layering Coupling in Modal Auto-Dismiss Timing**
  - **Source:** `src/components/save-reset-dialog.tsx:8` vs `src/lib/save-import.ts:10`
  - **Description:** `src/components/save-reset-dialog.tsx` directly imports `SAVE_DIALOG_DISMISS_MS` from `@/lib/save-import`. The `save-import.ts` library is responsible for client-side file decompression, entry validation, and format checking. Borrowing a UI timing constant (`1200ms`) from an import library to control the auto-dismiss behavior of a destructive storage reset modal creates an unnatural cross-feature coupling between two unrelated operations.
  - **Disposition:** *Fix now (Hygiene / Refactor)*. Relocate `SAVE_DIALOG_DISMISS_MS` to a neutral module (`src/types/save.ts` or a shared UI dialog constant module).
  - **Prevention:** Keep domain library modules strictly focused on parsing/business logic and declare UI interaction timing in UI-scoped constants.

- **Finding 4.3: Standalone Dual Implementations of `getByteLength`**
  - **Source:** `src/engine-plugins/Ropoductions_WebBridge.js:24-33` vs `src/lib/save-import.ts:69-71`
  - **Description:** Byte-length calculation is implemented independently in two locations: `Ropoductions_WebBridge.js` utilizes `Blob([str]).size` with an `encodeURI` fallback, whereas `src/lib/save-import.ts` uses `new TextEncoder().encode(str).length`. Because the engine plugin operates in a standalone vanilla JavaScript context inside an iframe and cannot import TypeScript modules from the Next.js host, the divergence is technically justified by runtime separation.
  - **Disposition:** *Accept as-is (Runtime Boundary)*. Document the runtime separation rationale.
  - **Prevention:** Re-verify that size limits in both runtimes match the declared 10MB per-slot and 50MB aggregate thresholds.

### Review Lenses (Adversarial, Edge Cases, Verification Gaps)

- **Finding 4.4: Missing Localized `saveExportError` Translation Key**
  - **Source:** `src/components/save-hud-dock.tsx:121-125` vs `src/locales/*.json`
  - **Description:** When an export operation fails in `SaveHudDock`, `handleExportClick` sets `exportError` to `error.message` (defaulting to `"Save export failed"`). Line 81 uses `exportError` directly as the button's accessible name and tooltip title. None of the six locale files (`en`, `es`, `ja`, `pl`, `ru`, `zh`) declare a `saveExportError` key. Consequently, in non-English locales, screen readers and title attributes surface raw, untranslated English technical error messages (e.g. timeout rejections or size limit errors) rather than a localized notification.
  - **Disposition:** *Fix now (Remediation / UX)*. Add `saveExportError` across all six locale files and update `SaveHudDock` to fall back to the localized message.
  - **Prevention:** Require all error state presentations to have explicit translation keys in UI specification matrices.

## Open Questions

- **Large Save Archive Streaming:** Currently, `MAX_TOTAL_ARCHIVE_SIZE_BYTES` is capped at 50MB in client-side decompression. For heavily modded or long-running game playthroughs, should future iterations consider streaming decompression via web workers if slot sizes expand?
- **Patreon Session Re-Verification During Long Play Sessions:** Lapsed patron detection occurs on route entry and asset requests. Consider whether an unobtrusive background re-check on save export should be added in Epic 5 to warn lapsed patrons before saving.
